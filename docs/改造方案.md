# 启航AI工作台 —— 改造方案

> 定位：基于本地笔记库的个人 AI 助手，数据本地化、模型自由、工作流数据体系完备，对话与 Agent 能力由官方 pi agent SDK 驱动。

---

## 1. 定位与差异化

| 卖点 | 含义 | 落地方式 |
|------|------|----------|
| 本地优先 | 笔记、索引、会话、任务全部存于本机，无外部存储依赖 | sql.js + 本机文件系统 |
| 模型自由 | 不绑定大厂模型，可插拔、可全离线 | 多模型配置（DeepSeek / Ollama / OpenAI 兼容） |
| 站在巨人肩膀上 | Agent 能力随 pi agent 升级自动演进 | 官方 SDK `@earendil-works/pi-coding-agent`，仅维护一层薄封装 |
| 自建数据体系 | 知识库/数据集/会话/待办/日报/飞书推送形成完整工作流 | `database.ts` + 各业务模块 |

**诚实边界（对外话术需注意）**：
- "数据安全"= 本地存储 + 模型可自选（Ollama 可全离线），而非"完全不出网"。对话内容默认仍发送给所配置的模型服务商。
- 前三项优势无硬护城河，真正粘性来自数据模型与工作流（日报、提醒、飞书推送、定时任务）。

---

## 2. 现状盘点（已完成的改造）

### 2.1 对话引擎迁移：LangChain orchestrator → pi agent SDK
- 工作台对话（`chat:send` / `coding:send`）已改为调用 `runPi()`（`electron/services/pi-agent.ts`），在主进程内直接运行官方 SDK，不再 spawn CLI 子进程（省去每次约 4.5s 启动开销）。
- 能力扩展走 pi 的 skill / extension / 自定义工具机制：
  - 已注册 `kb_search` 自定义工具（`defineTool`），进程内直接访问 `db` / `rag` 服务，不再依赖旧的 `~/.pi/agent/extensions/pi-kb-search.ts` 外部扩展。
- 会话续接：`SessionManager.open` 打开 `~/.pi/agent/sessions/assistant-v2-<sessionId>.jsonl`，与 CLI `--session` 同机制。
- 多模型切换：`resolvePiModel()` 把应用内 LLM 档案映射为 SDK 模型，`session.setModel()` 运行时切换。
- 事件桥接：`message_update` / `tool_execution_start` / `tool_execution_end` / `turn_end` → 前端兼容事件 `{type: start|end|thinking, name, error, text}`。

### 2.2 全量 TypeScript 迁移
- `electron/**` 全部 JS 迁移为 TS（13 个 services + main/preload/icon），`module.exports` → ES exports。
- 新增 `tsconfig.electron.json`（strict + noImplicitAny:false + strictNullChecks），输出到 `dist-electron/`。
- `package.json`：`main` → `dist-electron/electron/main.js`；新增 `compile:electron` 脚本；`electron:dev` / `electron:build` 前置编译。
- 编译状态：`npx tsc -p tsconfig.electron.json --noEmit` **0 错误**。

### 2.3 SDK 集成要点（后续升级时的已知约束）
- SDK 为 **ESM-only**，Electron main 为 CJS：用 `new Function('spec','return import(spec)')` 保留运行时真正的动态 import。
- `markAsUncloneable` polyfill：SDK 依赖的 undici 需要 `worker_threads.markAsUncloneable`（Node 22+ API，Electron 33 的 Node 20 没有），必须**直接 patch 真实模块 exports**（`const wt = require('worker_threads')`，不能走 `import * as`，否则 `__importStar` 包装对象导致补丁失效）。
- Electron 退出时调用 `disposeAll()` 释放 SDK 资源。
- SDK 类型不完整 → `skipLibCheck: true`。

## 4. 演进路线图

### 阶段一：对话统一到 pi agent（进行中）
目标：所有 AI 对话路径只走一条管道。
- [ ] 飞书消息回复改走 `runPi`（保留飞书特有上下文注入：项目选择、KB RAG 注入）
- [ ] 定时日报改走 `runPi`（系统提示词 + 用户格式要求模板化）
- [ ] 移除 `orchestrator.chat` / `agent.ts` 的 LangChain 调用路径
- [ ] 清理遗留 IPC（`agents:list` 等）
- [ ] 移除 `@langchain/*`、`langchain` 依赖并回归验证
- 验收：工作台、飞书、日报三路径均基于 SDK 事件流，`dist-electron` 产物体积下降，无 LangChain 引用。

### 阶段二：数据体系 × pi 工具融合
目标：把自建数据体系变成 pi agent 的一等公民能力。
- [ ] 数据集工具 pi 化：`query_dataset` / `list_datasets` 等迁入 `pi-agent.ts` 的 `defineTool` 注册表（替代 `tools.ts` 中 LangChain schema 定义）
- [ ] 新增工具：写笔记（`write_note` 已规划）、知识库建索引、数据导入导出
- [ ] RAG 增强：向量检索加入项目筛选、时间范围、目录过滤参数，供 kb_search 使用
- [ ] 图片能力验证：`session.prompt(..., { images })` 路径在多模型下确认可用
- 验收：`tools.ts` 中 LangChain 工具定义清零，所有工具由 pi 原生注册，RAG 命中率/工具调用成功率记录可观测。

### 阶段三：产品化打磨
- [ ] 对话停止/取消：`session.abort()` 接入前端（当前无停止按钮）
- [ ] 会话管理 UI：历史会话列表、删除、导出（JSONL/Markdown）
- [ ] 数据备份/恢复：memory.db + 笔记目录一键导出
- [ ] 离线模式验证：Ollama 全链路（对话 + 嵌入）无外网可用
- [ ] 打包配置：electron-builder `files` 明确包含 `dist-electron/**` 与 node_modules 生产依赖，验证 `npm run electron:build`
- 验收：断电/重启后数据完整，离线可用，安装包可独立运行。

### 阶段四：定位强化与运营
- [ ] README/帮助页按定位话术更新（本地优先 + 模型自由 + pi 生态）
- [ ] pi 升级跟踪流程：锁定版本 → 升级 → 跑通三路径回归 → 更新本文档
- [ ] 收集真实使用反馈，确定下一批自定义工具优先级（如"整理今日笔记"、"周报生成"）
- 验收：文档与实际架构一致；每次 pi 升级有明确回归清单。

## 5. 风险与依赖管理

| 风险 | 影响 | 缓解 |
|------|------|------|
| pi SDK 升级破坏兼容 | 对话功能中断 | 锁版本（当前 0.80.3）；`pi-agent.ts` 为唯一集成点，接口变化集中修改；升级后按阶段一回归清单验证 |
| SDK 类型不完整 | 编译期类型检查不足 | `skipLibCheck: true` + 集成层显式 `any` 边界类型 |
| Electron / Node 版本差距 | undici 等依赖需要新 API | 维护 `markAsUncloneable` 等 polyfill 清单（见 2.3），升级 Electron 时重新核对 |
| LangChain 遗留耦合 | 双引擎维护成本 | 阶段一全部迁移后删除 |
| "数据安全"话术风险 | 用户误解为完全不出网 | 对外明确"本地存储 + 模型可自选"，离线场景引导 Ollama |
